# Retain verified generated dependency recipes in the existing scope

Status: Accepted for portable tooling and bounded opt-in construction; production performance adoption remains pending.

Date: 2026-10-18

## Context

[ADR 3](3-generate-the-channels-package-versions-from-the-cohort-freeze.md) owns
cohort classification and exact source/metadata selection. [ADR 7](7-compose-applications-on-retained-keiro-runtime-baselines.md)
retains immutable runtime recipes and independently validates application scopes.
Full package conversion still happens during Nix evaluation. EP-19 moves declared
conversion work into explicit regeneration while preserving those contracts.

The one-root and five-root prototypes preserve derivations but miss the declared
evaluation threshold. Correct portable tooling therefore does not establish a
performance benefit or authorize moving production defaults.

## Decision

Use the existing typed `GenerationContext`, freeze parser and classifier. The
explicit `RecipeGenerationContext` adds compiler/system/channel, Nixpkgs, reviewed
policy, converter/extractor identities and supplied local archives/metadata.
Keep raw archive, unpacked NAR and Cabal-file hashes separate. Source-pin archive
metadata is verified independently without changing original solved observations.

Generate raw callable package functions and a portable manifest/extension through
the pinned builder's converter. Stage complete declared coverage, verify inputs
before and after conversion, and publish only to owned output directories. Offline
checking reconverts local inputs without replacing accepted artifacts. Preserve
format-1 bytes; explicit format 2 adds converted identity and component dependency
fields inspected from the exact function by Nix with symbolic arguments. These
names precede policy and final-scope resolution; they are not a second dependency
solver or a flattened runtime graph.

`mkGeneratedRecipeExtension` compares artifacts to the owning factory's separately
supplied validated context and actual builder/compiler. It verifies raw function
hashes, metadata identity and component fields, resolves dependencies in the final
recursive scope and applies reviewed policy once. Compiler checks stay inside each
package to avoid forcing the recursive compiler while constructing the extension.

The first-party factory's opt-in Hackage path checks selected cohort observations,
flags, index-state, versions/revisions and native argument mappings, then shares
the existing construction policy and compatibility capture. Undeclared roots keep
their constructors. Selected source pins and unavailable test arguments require
their existing owners or explicit support; there is no silent selected fallback.

Capture per-system/channel contexts and artifacts in a new runtime generation.
Both selected and independent reference factories consume that captured selection.
Its policy reference identifies an earlier reviewed generation; its own runtime
fingerprint also includes the new construction inputs. Neither value is native
support evidence. Older factories receive no new argument when their snapshots
lack the selection file. Hash actual projections as file bytes, including binary
archives, while retaining injected text-reader support for pure fixtures.

Freshness checks obtain converter arguments from the same Haskell model through
the read-only `cohort recipes commands` interface. The pinned converter's file-URI
route unconditionally creates a home cache. Build checks instead copy the exact
verified Cabal bytes into a private metadata-only directory, preserve every flag,
require `--no-hpack` and `--src-expression=src`, and compare output byte-for-byte
with the ordinary generator. This requires neither a home override nor a nested
writable Nix store. The behavior was inspected in `mori://nixos/cabal2nix`,
project-relative `cabal2nix/src/Distribution/Nixpkgs/Haskell/PackageSourceSpec.hs`
at `41239bcc0622a0975c6705a03a44dfeffeb56f23` (artifact-level source URI pending).

Keep exact generated bytes outside formatter coverage, including captured copies.
Ordinary evaluation and checks do not query Hackage or Mori for new selections.

Targeted maintenance defaults to the existing fixed-index updater, with its stock compiler
checked before staging or building. A successful no-op solve cannot replace a real
update/rollback rehearsal. Conflicting bounds require explicit wider-unlock direction;
the updater retains accepted artifacts and does not widen the request automatically.
An explicit `--advance-index-state` may select a strictly later elapsed UTC cutoff while retaining every unrelated source, metadata, flag and component identity. Validate against the original freeze header; never relabel old inputs. Stage the new cutoff separately and publish its common/inventory records together with the matching freeze/source/reports through concurrent-input and rollback guards. An index transition alone does not establish consumer or retained-generation acceptance.

## Validation and consequences

Require deterministic regeneration/relocation, rejection without writes, scoped
no-IFD, native converter freshness and exact dependency/consumer derivation parity.
Keep the independent runtime validator active. Whole-constructor no-IFD remains
limited by explicitly unconverted roots; `Diff` is the first observed boundary in
the generation-4 public constructor probe.

Generation 4 captures the bounded base64-bytestring configuration for both systems
and source channels. Its public constructors preserve all 273 non-boot runtime
derivations and the actual immutable Rei CLI derivation in all four cells. Broader
support remains unverified. [Both complete immutable platform gates](../evidence/ep19/retained-recipe-native-matrix.json)
pass, with 225 updater tests, 356 pure contracts, converter freshness and retained
parity. Apple-container execution of Linux binaries is
translated correctness evidence; it does not establish physical x86 performance.

The same GitHub-channel native CLI artifacts pass the existing cohort cache owner:
publication verifies the declared private/upstream providers, then new empty
alternate stores substitute 462 Darwin and 469 Linux paths with zero builds and
matching metadata. The Linux worker is the translated Apple guest. Its original
derivation and completed output cross a temporary binary cache to the host
publisher; all 2,933 build-closure metadata records agree after import. Preserve
these as bounded availability receipts, separate from broad runtime support,
hosted CI and the positive dependency-update rehearsal.

[EP-19](../plans/19-pre-generate-complete-locked-nix-haskell-dependency-recipes.md)
still owns targeted update/rollback, evaluation thresholds, total-cost accounting,
cache publication and production adoption. Retain failed experiments and keep
existing generations, aliases and consumer selections unchanged until acceptance.
